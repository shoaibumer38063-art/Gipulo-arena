# Task Summary 002 — Rules System Authored (all 17 rule files, v1)

```text
Task: Author the complete Gipulo AI rules system (foundation roadmap step 1), including the
      research-grounded canvas rules ("the main law of the canvas").
Date: 2026-10-11
```

**Problem being solved:** The vision document mandates a rules system BEFORE feature work —
internal engineering standards of a serious software company, not generic AI advice; and the
canvas-rules prompt demands deep research into how world-class tools (Figma, tldraw, Penpot, etc.)
build canvas systems, with strict separation of public fact / observable behavior /
recommendation / inference. As of task 001, `rules/` contained only a README plan.

**What was inspected:** All four canonical sources (esp. the canvas-rules prompt requirements =
`docs/memory/06`), the Design System HTML for binding micro-values (`docs/memory/07`), plus web
research: Figma's WebGPU rendering blog post (C++→Wasm engine, graphics-interface abstraction with
WebGL+WebGPU implementations, Dawn, dynamic fallback, native x64/arm64 compile for server-side
rendering/tests), Figma's Wasm load-time post, Figma's Mirror DOM accessibility post (internal
a11y tree with surgical updates, affine-transform positioning, bidirectional selection⇄focus
sync, coalesced ARIA announcements), tldraw public docs (camera {x,y,zoom}, screen/viewport/page
spaces with screenToPage/pageToScreen, hierarchical StateNode tool state machines, single active
tool routing, culling), Penpot public info (SVG-native model, real CSS layout semantics,
Rust+Wasm+Skia WebGL renderer, headless-Chromium exporter).

**Approach selected:** Author all 17 planned rule files at once as a coherent v1 set with a shared
epistemic tagging system ([PUBLIC]/[OBS]/[DS]/[REC]/[PROPOSED]/[INF]) and cross-referenced rule
IDs (CAN-*, UI*, CQ*, SM*, …), so every rule is citable and every value's authority is explicit.
Design decisions: canvas.md organized as 28 lookup sections with a binding micro-detail registry
(§27) and mandatory before/after change protocol (§28); [PROPOSED] values (drag threshold 3px,
hover hysteresis 2px, zoom clamp 2%–4096%, epsilons, tooltip/panel numbers, etc.) declared as
binding defaults until ADRs confirm them — so behavior stays consistent while decisions remain
open; Responsive Vector Segments given product-law status inside layout.md (L3) including the
user-mandated "never call it CustomClipper" communication rule; Figma's public architecture
patterns adopted as *principles* (engine/UI split, abstraction layer, state machines, mirror-DOM
a11y) with explicit non-mandate language — Gipulo does not commit to C++/Wasm now but keeps the
door architecturally open.

**Alternatives rejected:** (a) Writing only canvas.md now — rejected: the rules system is one
coherent operating system; partial rules leave agents guessing elsewhere. (b) Copying Figma's
stack as a mandate — rejected by the user's own requirement ("do not blindly copy"; research is
for principles). (c) Leaving all provisional numbers unspecified — rejected: unspecified values
produce inconsistent implementations; [PROPOSED]+ADR-gating gives consistency now and correctable
decisions later. (d) Presenting research findings without classification — rejected: the
canvas-rules prompt explicitly forbids passing inference off as public fact.
